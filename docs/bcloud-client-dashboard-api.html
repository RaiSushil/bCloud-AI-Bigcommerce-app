bCloud AI Search — Client Dashboard API

The APIs behind the merchant dashboard (portal.bcloudai.com), for a partner app that wants to show the same pages · October 2026 · No keys are written in this document.

1. What this is

The merchant dashboard at https://portal.bcloudai.com is a web app. It has no data of its own: every number on every page comes from sixteen small JSON endpoints under /client-api. A partner app can call the same endpoints and draw the same pages inside its own screens, for example inside a Shopify app.

One rule holds everywhere: a client's identity comes only from the session token it got at sign-in, never from the request body or the URL. One client can never read another client's data. A paused client loses access on its next call.

2. Base URL and sign-in

Base URLhttps://search.bcloudai.com/client-api  (the same endpoints are also served at https://portal.bcloudai.com/client-api)
FormatHTTPS, JSON in and out. Any origin may call (CORS is open), from a browser or from a server.
Sign-inPOST /login with the client id and the dashboard password. The answer holds a session token.
Every other callHeader Authorization: Bearer <token>
Token life8 hours. A 401 on any call means: sign in again.

POST /login

{ "client_id": "luna-jewels", "password": "..." }

→ { "token": "...",
    "client": { "client_id": "luna-jewels", "name": "Luna Jewels", "site_token": "...", "theme": null } }
  • Wrong id or password → 401. Too many wrong tries → 429 for a few minutes.
  • A paused or removed client → 401 "This account is not active".
  • theme is the client's own colours when set in bCloud's admin; otherwise null.

How a partner app should sign in

The merchant should not type a bCloud password inside your app. Your app already receives the client id and the dashboard password from POST /partner/signup when the store installs. Keep both on your app's server. When the merchant opens the dashboard page in your app, your server signs in, keeps the token for its 8 hours, calls the endpoints below and hands the JSON to your page. Nothing secret ever reaches the theme or the browser.

4. Each endpoint

GET /me

→ { "client_id": "luna-jewels", "name": "Luna Jewels", "site_token": "...", "theme": null,
    "created_at": "2026-10-12T09:10:00Z", "plan": { ... }, "products": 1840,
    "doctor": { "last_search_at": "2026-10-13T06:41:12Z", "last_sync": { ...the last run... } } }

products is the live count in the client's index. doctor.last_search_at is null until the first shopper search; doctor.last_sync is null until the first sync has finished.

→ { "funnel": { "searches": 1203, "clicks": 410, "orders": 37, "revenue": 2140.50 },     // this month
    "ctr_pct": 34.1, "conv_pct": 3.1,
    "clicks_total": 5120, "orders_total": 402, "revenue_total": 25880.00,
    "products": 1840, "searches_total": 15020, "searches_today": 86, "live_5m": 3, "avg_ms": 212.4,
    "ai_cost_month": 1.2345, "ai_tokens_month": 418000,
    "voice_total": 120, "voice_month": 31, "voice_cost_month": 0.0412,
    "image_total": 44, "image_month": 9, "image_cost_month": 0.0180,
    "zero_count": 61, "zero_top": [ { "query": "silver anklet", "count": 7 } ],
    "top": [ { "query": "gold ring", "count": 212, "avg_found": 38.5 } ],

zero_top is the missed-searches list: what shoppers typed and found nothing. ctr_pct and conv_pct are over all time; funnel is this month.

GET /live-sync

→ { "live_sync": { "active": false } }
→ { "live_sync": { "active": true, "finished": false, "indexed": 12400, "failed": 3, "total": 20000,
                   "percent": 62.0, "per_minute": 820.5, "cost": 0.4120, "tokens": 150000,
                   "elapsed_sec": 905.2, "started_at": "2026-10-13T06:30:00Z" } }

Cheap on purpose. Poll it every 2–3 seconds only while a sync is running; otherwise read it from /overview.

The money columns per query (clicks, orders, revenue, rates) are only on the all view, because shopper events are not tagged by door.

GET /events?type=all&size=50

type: all (default, hides impressions), view, impression, click, add_to_cart, wishlist, purchase. size 1–200. An unknown type → 400.

→ { "counts": { "view": 9000, "click": 5120, "add_to_cart": 900, "purchase": 402 },      // all time
    "today": { "view": 120, "click": 61, "purchase": 4 }, "today_revenue": 310.00, "live_5m": 3,
    "hourly": [ { "hour": "06:00", "events": 40, "clicks": 12, "orders": 1 } ],             // last 24 hours
    "recent": [ { "type": "click", "query": "gold ring", "product_id": "LJ-1021", "product_name": "Classic Gold Band",
                  "value": 0, "at": "2026-10-13T06:41:12Z", "source": "" } ] }

product_name is filled from the client's own catalogue when the product is found. For a purchase, value is the order value.

GET /products?q=ring&category=Rings&page=1&size=24

→ { "total": 312, "page": 1, "size": 24,
    "items": [ { "id": "LJ-1021", "name": "Classic Gold Band", "image": "https://...", "price": 199.0,
                 "category": "Rings", "brand": "Luna" } ],
    "categories": [ { "value": "Rings", "count": 312 }, { "value": "Necklaces", "count": 280 } ] }

Page 1–200, size 1–100. The fields are read through the roles the client registered (name, image, price, category, brand), so the answer has the same shape for every catalogue.

GET /billing

→ { "scope": "client", "client_id": "luna-jewels", "this_month": "2026-10",
    "current": { "month": "2026-10", "total_cost": 1.65, "ingest_cost": 0.41, "search_cost": 1.24,
                 "ingest_calls": 2, "search_calls": 2100, "days": 13 },
    "months": [ { "month": "2026-09", "total_cost": 3.10, ... } ],
    "all_time_cost": 4.75, "recent_days": [ ...14 days... ], "runs": [ ...up to 50 sync runs... ],
    "cloud": { "monthly_total": ... },
    "total_cost_of_ownership": { "month": "2026-10", "cloud_cost": ..., "ai_cost": 1.65, "total": ... } }

These are the client's own AI costs in US dollars, built from their sync runs and their shoppers' searches. The plan fee itself is agreed with bCloud separately.

GET /sync

→ { "registration": { "field_count": 28, "field_names": [ "sku", "title", "price", ... ], "registered_at": "..." },
    "runs": [ { "client_id": "luna-jewels", "finished_at": "...", "indexed": 1840, "failed": 0, "cost": 0.41, ... } ] }

registration is null until /fields/register has been called. runs holds the last 10 completed syncs, newest first.

GET /synonyms · POST /synonyms

GET  → { "synonyms": [ ["sofa", "couch"], ["ring", "band"] ] }

POST { "add": ["necklace", "chain"] }      → { "synonyms": [ ..., ["necklace", "chain"] ] }
POST { "remove": ["sofa", "couch"] }       → { "synonyms": [ ... ] }

Pairs of two words, lower-cased, up to 100 pairs. The search engine reads them at once. A pair already present is not added twice.

POST /change-password

{ "old_password": "...", "new_password": "..." }      → { "ok": true }

The new password needs at least 10 characters. A wrong current password → 401. If your app keeps the password on its server, update your copy at the same time, or the next sign-in fails.

GET /tickets · POST /tickets · POST /tickets/reply

GET  → { "tickets": [ { "id": "aB3...", "subject": "Search misses 'anklet'", "priority": "normal", "status": "open",
                         "created_at": "...", "updated_at": "...",
                         "messages": [ { "who": "client", "text": "...", "at": "..." },
                                       { "who": "support", "text": "...", "at": "..." } ] } ] }

POST /tickets        { "subject": "...", "message": "...", "priority": "normal" }     → { "ok": true, "id": "aB3..." }
POST /tickets/reply  { "ticket_id": "aB3...", "message": "..." }                        → { "ok": true }
POST /tickets/reply  { "ticket_id": "aB3...", "resolve": true }                         → { "ok": true }

Priority: low, normal, high. Status: open (bCloud's turn), pending (the client's turn), resolved. Subject 3–200 characters, message up to 4000. Only the client's own tickets are visible.

POST /assistant

{ "question": "Why are my searches for anklet finding nothing?",
  "history": [ { "who": "user", "text": "..." }, { "who": "blu", "text": "..." } ] }        // history is optional

→ { "answer": "...", "followups": [ "..." ], "goto": "analytics", "find": "anklet", "actions": [ ] }

Blu answers only from this client's own dashboard numbers. goto names a page worth opening, find a word to search there; both can be null. When the merchant asks for it, Blu can add or remove a synonym or raise a support ticket; what it did is listed in actions. Limit: 20 questions per client per 10 minutes (429). If the AI is busy → 503, try again shortly. This endpoint is optional for a partner app.

5. Where the numbers come from

The dashboard invents nothing. Every page is a view of six stores that are filled by the store's own activity: shoppers searching, the connector syncing, the merchant writing to support. Your app reads them through /client-api, which only ever returns the signed-in client's rows.

6. Errors

CodeMeaningWhat your app should do
401No token, expired token, wrong password, or the client is pausedSign in again. If sign-in also fails with "not active", show "search is paused" and stop polling.
400Unknown event typeUse one of the listed values.
404Ticket not found (or not this client's)Refresh the ticket list.
422The body is the wrong shape (missing field, too long, bad priority)Fix the request; the answer names the field.
429Too many wrong sign-ins, or the assistant's budget for 10 minutes is usedWait a few minutes.
503The assistant could not think right nowShow "try again in a moment".

7. How often to call

EndpointSuggested rhythm
/loginOnce, then keep the token for 8 hours; sign in again on a 401.
/me, /billing, /sync, /synonyms, /tickets, /productsWhen the page opens, and on a refresh button.
/overview, /analyticsWhen the page opens; refresh every 30–60 seconds if the page stays open.
/eventsEvery 5–10 seconds while the live-activity page is open.
/live-syncEvery 2–3 seconds only while active is true; stop when it turns false.

Layout

  • Left sidebar, glass, 224 px wide (an icon rail of 76 px on tablets, a bottom bar on phones). Four groups with small pink group labels: Monitor (Overview, Analytics, Live activity, Missed searches), Catalogue (Products, Data sync, Search settings), Money (Billing), Account (Install & keys, Support). Settings and sign-out sit in the header.
  • Content: a welcome card, a row of KPI tiles, then full-width panels with charts and tables. Recharts for every chart; one data point shows as a full-width block, never a single dot.
  • Blu, the assistant, is a bubble at the bottom right; it opens a chat sheet.

Motion

A sync is runningthe live-sync card shows a moving bar and a cost that ticks; it stays 90 s after the run completes

Loadinga small 3D loader (ld3): a box that breathes and floats over a glowing ring with the bCloud chip

Reduced motionwhen the visitor's system asks for reduced motion, every animation is off and numbers simply appear

Inside a Shopify embedded app you will use Polaris for the frame. Keep Polaris for navigation and forms, and keep the portal's violet accent, the KPI count-up, the live dot and the staggered card entrance for the content. That is enough for a merchant to recognise the same product in both places.
